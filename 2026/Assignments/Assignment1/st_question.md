### Q17: 為什麼取第 4 個字為正確答案？一定要轉小寫嗎？

### Q35: `np.array()` 是什麼？為什麼不直接用 Python List？
* **學生提問**：「np.array( ) 是什麼是numpy 是什麼去了 這是它裡面的函式功能是專門在做什麼 array不是陣列嗎」
* **核心解析**：
  * **NumPy (Numerical Python)**：Python 科學計算與 AI 的底層核心引擎。
  * **Python List vs NumPy ndarray**：
    * List 是非連續記憶體指標鏈結，不支援真正的矩陣數學加減（`[1, 2] + [3, 4]` 會變成拼接串列 `[1, 2, 3, 4]`）。
    * NumPy Array 是以 C 語言連續記憶體配置建構，支援向量化廣播運算與高速矩陣分解（`array([1, 2]) + array([3, 4])` 為 `array([4, 6])`）。
  * **在代碼中的角色**：`np.array([model[w] for w in words])` 將 46 個單字的 100 維向量打包成形狀為 `(46, 100)` 的連續數值矩陣，提供給後續只接收 ndarray 的 t-SNE 演算法運算。

* **核心解析**：
  * **所屬套件**：來自著名的機器學習庫 **Scikit-learn**（`from sklearn.manifold import TSNE`），屬於流形學習（Manifold Learning）非線性降維工具。
  * **全名與目的**：t-Distributed Stochastic Neighbor Embedding，專為高維數據可視化設計，相較於 PCA 能更好地保留局部鄰近關係，避免擠壓重疊。
  * **參數拆解**：

### Q37: `.fit_transform()` 是做什麼的？屬於哪個套件？

    3. `fit_transform(X)`：將上述兩步合而為一，**「一邊學習空間結構，一邊直接把降維後的結果算出來吐給我們」**。

### Q51: 為什麼 Word2Vec 不用 GPU 加速？GPU 密集計算 vs CPU 稀疏查表深度解析
* **學生提問**：「用gpu 不會比較快嗎」

  2. **Gensim 底層無 GPU 支援**：Gensim 的 `Word2Vec` 是用 C/Cython 編寫的，只編譯了 CPU 的指令集（AVX/SSE）與 POSIX 多執行緒，根本沒有寫 CUDA / GPU 驅動代碼。開 GPU 時，GPU 使用率依然是 0%，全部仍由 CPU 默默運算。
  3. **算法物理特性的本質差異（為什麼 Word2Vec 不適合 GPU？）**：
     * **GPU 的強項**：大規模「密集矩陣乘法」（Dense Matrix Multiply），如 Transformer、BERT、LLM。
     * **Word2Vec 的特性**：本質是「**極端稀疏的查表更新（Sparse Lookup & Update）**」。滑動窗口每次只取幾個字與負樣本，微調特定的幾行向量。

  4. **Colab Pro 真正能加速 Word2Vec 的升級秘訣**：
     * 不是切換到 GPU，而是在執行階段類型切換為「**高 RAM (High-RAM)**」。

### Q98: Colab Markdown 排版優化技巧（消除雙重縮排與醜陋破行）

     * **病灶三：縮排缺乏層次**：子要點（Sub-bullets）未按規定縮排 3~4 個空格，造成視覺上下層級混亂。
  2. **高分排版標準公式**：
     * 大項目使用乾淨的 `1.`、`2.`、`3.`。
     * 子要點縮排 3 個空格並使用 `*`。

### Q105: `punkt` 與 `punkt_tab` 斷句分詞模型之功能與版本相容性
* **學生提問**：「`nltk.download('punkt', quiet=True)`、`nltk.download('punkt_tab', quiet=True)` 這兩個又是什麼」
* **核心解析**：
  1. **為什麼電腦斷句不能只靠 `split('.')`？**：
     * 英文句點具備多重語義：既是句尾符號，又是縮寫標記（如 `Mr.`, `Dr.`, `U.S.A.`, `vs.`, `etc.`）或小數點（`3.14`）。
     * 若直接以句點切割，句子會被截成破碎片段。
  2. **`punkt` 是什麼？（無監督斷句分詞大腦）**：
     * 基於 Kiss & Strunk (2006) 經典論文之無監督句子邊界檢測模型（Punkt Sentence Tokenizer）。
     * 預先學習了海量縮寫詞彙庫與句法模式，`gutenberg.sents()` 在背後即是調用 `punkt` 模型來精準判斷真正的句子起迄點。
  3. **為什麼新版還要下載 `punkt_tab`？（新舊版本防呆雙保險）**：
     * **歷史沿革**：NLTK 於 3.9+ 版（2024~2026）將預編譯分詞查找表（Tokenizer Table）由原本的單一 pickle 檔重構成獨立資料包 `punkt_tab`，以提升多語言分詞效能與載入安全性。
### Q106: 分佈假說（Distributional Hypothesis）之哲學起源、數學實現與反義詞死穴
* **學生提問**：「甚麼是word2vec分布假說」
* **核心解析**：
  1. **核心名言（Firth, 1957）**：
     * *"You shall know a word by the company it keeps."*（觀其伴，知其意）。
     * **核心哲學**：單詞的「意義」不是由字典裡的靜態文字給定，而是由它在海量文本中**「經常與哪些上下文（Context）一起共現」**所決定的。
  2. **經典案例（Tezguino 假想詞實驗）**：
     * 即使你從未見過虛構單字 *Tezguino*，但在看到「桌上有一瓶 Tezguino」、「喝了 Tezguino 後喝醉了」、「夏天需要冰涼的 Tezguino」等句子後，人類大腦會依據上下文自動推斷它是「某種酒精飲料」。Word2Vec 即是將此認知過程完全數學化。
  3. **Word2Vec 的幾何數學化機制**：
     * 透過滑動窗口（Window Size）抓取共現詞對。
     * CBOW 以周圍詞預測中心詞，Skip-Gram 以中心詞預測周圍詞。
     * 藉由最大化共現詞對的向量點積（餘弦相似度），使上下文相似的詞在高維向量空間中自動聚類（如 $\vec{king} - \vec{man} + \vec{woman} \approx \vec{queen}$）。
